# 35 · одночасні запити: списання одним запитом

**Як перевіряється:** `check` відкриває **2 з'єднання** і виконує твій `my.sql` в обох одночасно. Потім дивиться на стан таблиці.

```
accounts: id 1, balance 100

два запити "спиши 80" одночасно:
  правильно:  перший списав → 20, другий відмовлено → лишилось 20
  неправильно (update без умови): 100 - 80 - 80 = -60
```

Чому `update ... where balance >= 80` безпечний: `update` бере замок на рядок. Другий запит чекає коміту першого, а потім **перечитує рядок** і перевіряє умову вже на `balance = 20`. Умова не проходить, оновлено 0 рядків.

**Завдання:** спиши 80 з рахунку `id = 1` одним `update`, який не дасть балансу піти в мінус. Додай `returning balance`, щоб у `npm run play` бачити, чи списання відбулось (1 рядок) чи ні (0 рядків).

**Таблиця:** `accounts`
